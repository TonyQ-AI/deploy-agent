# 通用自动化部署系统（多项目共用）

> 一套基础设施，所有项目共用：本机开发 → GitHub 版本管理 → 服务器自动化部署。
>
> 📦 本系统独立维护于私有仓库 **github.com/TonyQ-AI/deploy-agent**（脚本/模板/文档以此为准）
> ✅ 已实战验证（MediaManager-online 2026-08-14，当前服务 2 个项目）。
>
> ⚠️ **适用范围**：仅内网/局域网 Windows 服务器（本机可通过 SMB 共享访问）。
> 云服务器（公网可达）请直接用 GitHub Actions，本系统不适用（见《接入决策指南》）。

---

## 1. 系统架构

```
【本机】deploy.ps1（每项目一份，templates/deploy.ps1.example 复制）
  ① git commit + push（版本管理/回滚）
  ② 构建（npm run build / 其他）
  ③ robocopy 同步代码+dist 到服务器（正斜杠 UNC）
  ④ 写部署标志 .deploy-flag（含版本时间戳）

【服务器】C:\deploy-agent\（装一次，永久共用，配置驱动）
  ├── scripts/watcher.ps1      单实例进程（恒定 ~20MB），每 3 秒轮询所有项目标志
  │                            → 变化则调用该项目 restart.cmd → 删标志 → 写日志
  ├── scripts/daily-check.ps1  每日 02:00 兜底（SYSTEM 任务）
  │                            ① 标志残留（watcher 漏了）→ 补执行重启
  │                            ② watcher 进程死了 → 自动拉起
  └── projects.config          项目清单（新项目 = 加一项）

【计划任务】（服务器，注册一次永久有效）
  ├── <项目>-watcher   AtStartup + SYSTEM → watcher.ps1（开机即启，无人值守）
  └── DeployAgentDaily 每日 02:00 + SYSTEM → daily-check.ps1
```

## 2. 资源占用（多项目依然恒定）

| 资源 | 占用 | 说明 |
|------|------|------|
| 内存 | ~20MB 恒定 | 单实例进程，与项目数量无关 |
| CPU | ~0% | 每 3 秒读 N 个文件时间戳（元数据查询，走系统缓存）|
| 磁盘 | ≈0 | 无物理读写（元数据在内存缓存）|

> 对比：每 3 秒一次本地元数据查询比每分钟一次网络请求轻两个数量级。

## 2.5 局域网共享准备与路径确认（接入前必读）

> ⚠️ 本系统依赖"本机 → 服务器"的 SMB 文件共享，**每个人的共享方式不同，先确认你的路径格式**。

### 2.5.0 先确定服务器地址（主机名或 IP）

部署前必须先知道服务器的**主机名或局域网 IP**，这是所有 `//服务器/...` 路径的前缀。获取方式（任选）：

| 方式 | 操作 |
|------|------|
| 服务器上查 | 在服务器执行 `hostname`（主机名）或 `ipconfig`（IPv4 地址）|
| 问管理员 | 向维护服务器的人要"主机名 + 共享名"|
| 本机自动发现 | 本机 `net view` 列出局域网所有共享主机（找到目标服务器名）|
| 本机 ping | `ping <主机名>` 能通 = 网络可达 |

**示例**：服务器主机名 `DESKTOP-ABC123`、IP `192.168.1.50` → 后续路径写 `//DESKTOP-ABC123/...` 或 `//192.168.1.50/...`（两者皆可，主机名更稳定）。

> ⚠️ 服务器地址可能变化（DHCP 重新分配 IP），建议：**优先用主机名**，或给服务器设置固定 IP。

### ⚠️ 防错关键：确认你连的是"部署服务器"（不是随便一台电脑）

**局域网里通常有多台电脑**（开发机、旧电脑、NAS 等），`net view` 会列出所有主机——**本系统只连"部署服务器"这一台**（装有 `C:\deploy-agent\` 的那台），连错机器会导致部署落错位置、数据错乱。

**接入前必须做"服务器身份确认"**（三选一即可）：

| 确认方法 | 操作 |
|---------|------|
| 检查部署目录 | 连上共享后确认存在 `C:\deploy-agent\projects.config`（这是部署系统的标志）|
| 检查项目根 | 确认共享里有 `runserv\` 目录（所有项目都部署在 `E:\runserv\` 下）|
| 询问管理员 | 直接向部署管理员确认主机名/IP，不要凭印象猜 |

**常见事故**：新项目凭记忆填了服务器地址，结果连到局域网里另一台电脑（开发机/旧机器），部署全部落错位置、服务器上毫无动静。**务必先用上述方法确认，再填 `$Remote`。**

> 📌 本部署系统服务器（当前环境）：
> - 主机名：**DESKTOP-GHDR9LC**
> - 局域网 IP：**192.168.0.104**（同一台机器，主机名或 IP 皆可）
> - 项目根：`E:\runserv\`

### 2.5.1 服务器端：把项目目录共享出来（一次性）

在服务器上，右键项目根目录（如 `E:\runserv`）→ **属性 → 共享 → 共享**，选择账户并设置**读写权限**。

### 2.5.2 确认你的共享路径格式

在服务器上执行 `net share` 查看共享名，然后对照：

| 共享方式 | UNC 路径（正斜杠写法）| 示例 |
|---------|----------------------|------|
| 共享整个盘符（如 E 盘）| `//服务器/E/项目路径` | `//server/E/runserv/项目名` |
| 共享某个目录（如 runserv）| `//服务器/共享名/项目路径` | `//server/runserv/项目名` |
| 共享用户目录 | `//服务器/Users/用户名/...` | `//server/Users/admin/项目名` |
| 映射网络驱动器（本机 Z:）| `Z:/项目路径`（无 // 前缀）| `Z:/项目名` |

### 2.5.3 本机连通性测试（关键一步）

```
Win+R → 输入 \\服务器\共享名 → 回车 → 能打开并看到项目目录 = 通过
```

或命令行：

```cmd
dir \\服务器\共享名
```

**测试通过后**，把实际路径填到 deploy.ps1 的 `$Remote`（**必须用正斜杠**，见第 5 节边界）：

```powershell
$Remote = '//服务器/共享名/项目路径'   # 用你的实际路径替换
```

### 2.5.4 常见问题

| 问题 | 处理 |
|------|------|
| 看不到共享/提示没有权限 | 服务器端确认共享了**读写**权限；Windows 11 家庭版需先开启 SMB 客户端功能 |
| 需要用户名密码 | 本机先 `net use \\服务器\共享名 /user:xxx 密码` 建立凭据 |
| 映射驱动器后脚本用 Z: | `$Remote = 'Z:/项目路径'` 同样可用（正斜杠）|
| 服务器共享名含空格 | 正常使用，正斜杠路径不受影响 |

### 3.1 服务器：projects.config 加一行

`C:\deploy-agent\projects.config`：

```json
[
  { "name": "MediaManager-online", "path": "E:\\runserv\\MediaManager-online", "flag": ".deploy-flag" },
  { "name": "新项目名",           "path": "E:\\runserv\\新项目名",            "flag": ".deploy-flag" }
]
```

改完**不需要重启 watcher**——每轮询周期自动读配置（下次部署前生效；或重启 watcher 立即生效）。

### 3.2 服务器：项目目录 + restart.cmd

```
E:\runserv\<新项目>\
├── 项目文件...
├── logs\                 # 项目日志目录（watcher.log 自动写入）
├── .deploy-flag          # 标志文件（deploy.ps1 自动写入，无需手建）
└── restart.cmd           # ★ 唯一需要定制的文件
```

`restart.cmd` 模板（端口预检 + 幂等重启）：

```cmd
@echo off
rem <项目名> restart (idempotent)
taskkill /F /IM <你的进程名>.exe > nul 2>&1
timeout /t 2 /nobreak > nul
start "" <你的启动命令>
```

### 3.2.1 端口规范（安全实践）

**新项目服务监听端口请使用不常用端口**（如 `4xxxx`~`6xxxx` 高位随机端口），避开常见端口：

| 常见端口（避免使用）| 说明 |
|---------------------|------|
| 80 / 443 | HTTP/HTTPS 默认端口，扫描器最爱 |
| 3000 / 8080 / 8888 | 开发/代理常见端口，极易被扫描命中 |
| 5000 / 8000 / 9000 | 各类框架默认端口 |
| 3456（本项目用）| 本系统 MediaManager 已占用，新项目避开 |

**推荐做法**：
- 选一个高位随机端口，如 `4xxxx`~`6xxxx` 区间（如 45678、52341）
- 项目配置里用**环境变量**指定端口（如 `PORT=45678`），不要硬编码
- 配合 Cloudflare Tunnel：域名只暴露 `mm-online.top` 这类入口，**本地端口不出公网**（隧道模式下端口本身不可达，但局域网内仍建议避免常见端口，降低被扫描/探测的风险）

> 📌 参考：MediaManager-online 用 3456、yunjing 用 3457——新项目建议选择与现有项目**不同的高位端口**，避免冲突且更难被猜中。

### 3.3 本机：deploy.ps1（复制模板改 3 处）

```powershell
# 改这 3 个配置：
$Remote = '//<服务器>/E/runserv/新项目名'   # ① 同步目标（正斜杠 UNC！）
npm run build                                # ② 构建命令
robocopy "$PWD\dist" "$Remote\dist" ...      # ③ 产物目录
# ④ 写标志（照抄）：
echo "deploy-$(Get-Date -Format yyyyMMddHHmmss)" | Set-Content '//<服务器>/E/runserv/新项目名/.deploy-flag'
```

### 3.4 使用

```powershell
# 本机：一键部署（push + 构建 + 同步 + 触发）
powershell -ExecutionPolicy Bypass -File deploy.ps1

# 服务器：3 秒内自动重启生效；每日 02:00 兜底；watcher 崩溃自动拉起
```

## 5. 已知边界

| 边界 | 说明 |
|------|------|
| SMB 事件通知不可靠 | 曾用 FileSystemWatcher 事件驱动，SMB 跨机写入收不到通知（实测 3 版失败）→ 改用轮询，100% 可靠 |
| 服务器不构建 | dist 等产物一律本机构建后同步（服务器构建环境兼容性不可控）|
| git 凭据 | 服务器 SYSTEM 任务用 `C:\Windows\System32\config\systemprofile\.git-credentials` |
| 部署延迟 | 标志写入后 ≤3 秒生效（轮询周期）|
| ⚠️ UNC 路径必须用正斜杠 | PowerShell 脚本里写 `//服务器/共享/路径`（正斜杠）。**反斜杠 UNC `\\服务器\...` 在脚本里极易被转义成单反斜杠 → 变成本地路径（实测：robocopy 全写到本机 E:\<误写目录>\）**。bash 与 .NET 均接受正斜杠 UNC |
